# 闸对

中文名：**闸对** · 前缀 `gatetwin` · 端口 **6500 / 11500**

## 骨架

**刷卡点装载 → 同卡进站出站成对物化 → 缺腿/异向/超时旁路 → 行程账与刷卡点互证**

皮：地铁/公交闸机刷卡。去皮是 **OD 成对管道 + 开腿态 + 旁路 + 行程贯验**，不是票务售票 CRUD、不是乘车码业务页、不是日结封账。

## 冒烟

```bash
docker compose up -d --build
# http://127.0.0.1:6500
# 刷卡流 → 灌「成对样例」→ 看开腿账/行程账 → 再灌「缺腿超时样例」「出站孤儿样例」→ 行程贯验
```

## 主链对象

| 对象 | 作用 |
| --- | --- |
| 刷卡点 | 带卡号/站点/方向/事件时的进出闸事件 |
| 开腿账 | 已进站尚未出站的在途开腿 |
| 行程账 | 进站+出站成对后的正式行程 |
| 旁路匣 | 缺腿超时 / 出站孤儿 / 重复进站等 |
| 行程贯验 | 成对刷卡 ↔ 行程笔数 ↔ 旁路命运互证 |

## 卡号换绑隔离（已落地）

全局贯彻唯一架构——**口径甲：切断旧开腿旁路**（不采用「开腿随新卡迁移」）：

- 换绑写闸与开腿处置在同一 `BEGIN IMMEDIATE` 事务，禁止半截迁移；
- 事务内旧卡**全部在途开腿旁路**（`旁路原因=换绑切断`，入旁路匣），新卡从空开腿开始；
- **开腿账行卡号不可改写**：行程账卡号恒取开腿卡号，故「行程卡号 ↔ 开腿卡号 ↔ 进站刷卡卡号」恒等，无撕裂面；
- 换绑后旧卡再出站 → 出站孤儿；新卡出站只配换绑后新腿，与原进站不成对；
- 写闸（valid=0 不处置任何腿并留审计）：新旧卡相同 / 旧卡已有生效换绑 / 新卡自身有在途开腿；
- 接口：`POST /api/换绑`（写闸）、`GET /api/换绑?旧卡=&新卡=`（只读：旧卡、新卡、处置列表、审计、valid）；
- 贯验新增：行程卡号↔开腿卡号撕裂、生效换绑后旧卡在途腿清零、切断腿状态/原因/卡号未改写、valid=0 无处置、已旁路腿原因自洽。
